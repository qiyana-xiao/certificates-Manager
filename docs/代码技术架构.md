# 证件管家（Doc Keeper）代码技术架构

> 文档版本：1.0
> 更新时间：2026-09-27
> 面向读者：开发者。业务背景与产品说明见同目录《项目介绍.md》。

## 1. 架构结论

证件管家是一个前后端分离的模块化单体 Web 应用，核心是一个**确定性提醒引擎**驱动"证件到期 → 主动提醒 → 续办指南"的闭环。代码由 AI 辅助生成（Trae），开发者负责设计数据模型、提醒正确性规则、权限与授权边界，并能够用自己的话讲清每一段在做什么：

- 前端使用 Vue 3 + Vite，负责证件档案、到期日历、首页仪表盘、续办指南页面与浏览器端会话状态。
- 后端使用 Python 3.11+ + FastAPI + SQLAlchemy 2，负责认证、权限、**提醒调度与去重**、到期计算、数据访问。
- MySQL 8.0 是唯一业务数据库，库名 `doc_keeper`。**提醒的幂等与"每天只提醒一次"由数据库唯一索引保证，不由进程内存保证。**
- Redis **不是业务数据源**，仅缓存提醒去重键、限流计数、JWT 注销黑名单和首页聚合等**可重建状态**。清空 Redis 不会丢任何档案与提醒计划。
- 不拆分微服务，不使用开机自动建库建表，不使用外部定时/推送调度平台。
- 系统有两类角色：`user`（普通用户，含家庭管理员）、`admin`（知识库维护）。

```text
Browser
  Vue + Vite :5173
       |
       | /api proxy
       v
FastAPI (UVicorn) :8000
  |          |          |
  |          |          +-- 提醒调度器（进程内定时重扫）
  |          +------------- Redis（可选）
  +------------------------ MySQL doc_keeper
```

### 1.1 一句话区分：任务清单 vs 到期管家

普通的待办清单是"你想起来才看到提醒"。证件管家是**系统按到期时间主动找你**，并且给的是"怎么办"的落地答案（材料/地点/费用/时限/官方入口）。提醒来自数据库真实到日期，续办指南来自政务官方办事指南——系统的每一条结论都站在真实数据上，这是本项目的立身之本。

## 3. 提醒引擎（核心章节）

### 3.1 循环本体

`services/reminder_engine.py` 是整个项目的心脏，换掉所有包装后只有这些事：

```python
# 伪代码，真实实现含锁、分批、异常兜底
def scan_and_emit():
    for doc in db.query(MyDocument).filter(MyDocument.status.in_(VALID, EXPIRING)):
        for rule in doc.reminder_rules:                 # 多档提前量
            due = rule.ahead_days                      # 提前天数，如 90/30/7
            remind_date = doc.expire_date - timedelta(days=due)
            if remind_date == today(doc.user_tz):      # 今天正好到点才发
                _emit_once(doc, rule)                  # 幂等：同键只发一次

def _emit_once(doc, rule):
    key = f"reminder:{doc.id}:{rule.id}:{today}"
    if not cache.set_nx(key, ttl=24h):                 # Redis 快通道“已发”
        return
    db.upsert(ReminderJob(doc_id, rule_id, date=today, status=EMITTED))
    notify_user(doc, rule)                             # 落库一条“提醒已发”
```

**关键认知**：模型/外部平台只负责被调用，**判断和去重永远发生在应用进程里**。系统不依赖任何"想起才检查"的人工行为，今天到点的提醒今天一定会扫描到。数据库 `reminder_jobs` 唯一索引 `uk_doc_rule_date (document_id, rule_id, remind_on)` 是"同一天同一张证同一档只提醒一次"的**最终保证**。

### 3.2 到期计算：正确的日期才是硬功夫

`services/expiry_calc.py` 处理所有复杂的到期推导，**日期永远以用户登记的时区为边界，不用服务器本地时间**：

| 情况 | 规则 |
| --- | --- |
| 明确到期日 | 用户手填的到期日即为基准 |
| 按有效期自动算 | 起始日 + N 年/N 月，跨月跨年（含闰年 2/29）精确推算 |
| 只到月/年 | 如"到2027年6月"，按当月月末/该年年末归一 |
| 到期判定 | 到期日 − 今日 ≤ 0 → 过期；≤ 提前档 → 临期；否则未到 |

- 快照一致性：到期日变更后，重算该证的临期/过期状态并刷新日历聚合；
- 状态只算不计（`status` 存储的 `VALID/EXPIRING/EXPIRED` 由到期计算服务刷新，不靠用户手改）。

### 3.3 幂等与每日一次

同一张证、同一档规则、同一天，理论上可能被 `scan_and_emit` 多次碰到（重启重扫、多进程误跑）。三道防线：

1. **Redis 快通道**：`SETNX reminder:{doc}:{rule}:{date}`（TTL 24h），命中即跳过，保证一次进程内也最多发一次；
2. **数据库唯一索引**：`reminder_jobs (document_id, rule_id, remind_on)` 唯一，就算 Redis 没了、进程重跑，重复插入也会被唯一索引拦下；
3. **绝不静默吞掉**：重复写被拦后记为告警日志，便于排查，不影响正常用户。

### 3.4 时区

用户 `users.default_timezone`（默认 Asia/Shanghai）。所有"今天是否到点"判断都用 `zoneinfo / pendulum` 换算到用户本地东八区，避免跨时区差一天。日期字段一律存 `DATE`（无时区），仅"何时提醒"的判断涉及时区换算。

### 3.5 触发方式（双保险）

- **进程内调度**：FastAPI 启动时用 `asyncio.create_task` + 循环 `await asyncio.sleep(interval)` 拉起的定时扫（默认每分钟一次，只扫状态有效/临期的记录）；
- **每日兜底重扫**：每天本地 00:00 再全量重扫一次，把漏掉的历史到期日补齐；Redis 不必常驻，丢了下一条由 DB 唯一索引兜底，**不会出现"当天该提醒却没人提醒"**。

### 3.6 兜底与降级

| 故障 | 行为 |
| --- | --- |
| Redis 不可用 | 提醒去重走数据库唯一索引（仍正确），缓存类功能降级为进程内；不丢档案与提醒计划 |
| 数据库连接异常 | 本次扫描跳过并告警，不假意通知成功；下次扫描自动恢复 |
| 单条证件数据异常 | 跳过该条、记日志，不影响其余证件提醒 |
| 到期计算异常 | 该证件按"临近默认安全值"降级处理并告警，绝不编造到期结论 |

## 4. 后端分层

### 4.1 Router 层

| Router | 路由 | 责任 |
| --- | --- | --- |
| `health` | `/api/health`、`/api/health/ready` | 存活、MySQL/Redis 就绪检查 |
| `auth` | `/api/auth/**` | 注册（选 user）、登录、当前用户、注销、资料更新（省份） |
| `documents` | `/api/documents/**` | 证件档案增删改查 |
| `calendar` | `/api/calendar` | 到期日历月视图聚合（按到期日分组、按临期分级） |
| `reminders` | `/api/reminders/**` | 我的提醒列表、设置提醒规则、标记已处理 |
| `guides` | `/api/guides/**` | 续办指南查询（登录用户，含本省版/全国版）、增删改（管理员） |
| `regions` | `/api/provinces` | 省份列表（名称、交管码、政务平台入口），登录用户 |
| `family` | `/api/family/**` | 家庭成员/分组共享管理 |
| `export` | `POST /api/export` | 档案与提醒导出 CSV |

异常由 `main.py` 统一异常处理转换为 `{ "error": "错误信息" }`。

### 4.2 Service 层

- `reminder_engine`：调度扫描与幂等去重（本章核心，唯一常驻调度服务）；
- `expiry_calc`：到期日正确性、临期/过期状态刷新，是**全站到期口径的唯一来源**。
- 其余业务逻辑（证件 CRUD、日历聚合、提醒规则、指南维护、家庭、导出、认证）按快路径**直接写在对应 Router 之上**（见 4.1），不另拆 service 文件；认证与敏感字段 AES 加解密在 `security.py` 中合著实现。

### 4.3 数据访问

SQLAlchemy 2 声明式 `models/` 对应 12 张表；查询聚合（日聚合、临期分级）写在 service 层或使用 SQL 原生聚合；所有时间、到期判断集中在 `expiry_calc`，避免各处重复、口径不一致。

## 5. 认证与权限

### 5.1 注册与密码

1. 用户名 2-20 位中文/字母/数字/下划线；密码至少 8 位且不得为常见弱口令；
2. 注册时自选角色 `user`（默认；家庭成员共享为 user 内的分组能力）；
3. **密码一律不明文存储**：使用 `Argon2`（`argon2-cffi`）单程哈希写入 `users.password_hash`，不可还原；即使数据库泄露，原始密码也不暴露；
4. 登录统一走 Argon2（或 BCrypt）校验，并配合登录限流（见 5.4）防爆破；
5. 默认不创建管理员：`admin` 由数据库授权 `UPDATE doc_keeper.users SET role='admin' WHERE username=?`。

### 5.2 JWT 认证

`core/security.py` 使用 PyJWT HS256 签发，载荷含 `sub`、`username`、`role`、`iat`、`exp`。"密文"与防伪由 JWT 的签名机制承载——Token 带数字签名，任何篡改在服务端验签时直接判失败。

- **短时效 Access Token**：`JWT_ACCESS_EXPIRE_MINUTES`（默认 60 分钟），降低泄漏窗口；
- **Refresh Token**：`JWT_REFRESH_EXPIRE_DAYS`（默认 7 天），过期后可用其换取新 Access Token，避免反复登录；
- **注销即失效**：退出登录把 `jti` 写入 Redis 黑名单（TTL 等于残余有效期）；支持按会话撤销，未撤销的 Token 无法被冒充继续使用；
- **密钥只从环境变量 `JWT_SECRET` 读取**，长度不足 32 字节拒绝启动；`core/deps.py` 依赖注入校验 Bearer Token 写入请求上下文。

### 5.3 敏感字段密文加密（证件号落库）

证件号等属**极高敏感**字段，采用对称加密"密文落库"：

- **加密算法**：AES-256-GCM（`cryptography` 库），带 GCM 认证标签，防篡改、防窃取；
- **密钥来源**：环境变量 `ENC_KEY`（Base64 编码的 32 字节密钥），**不写进数据库、不提交仓库**；
- **存储**：`my_documents.doc_number_cipher` 存密文（Hex/Base64），数据库层面看不到明文；
- **使用**：仅在"用户查看详情 / 导出本人数据"等明确需要时，由 `encryption_svc` 用 `ENC_KEY` 解密，且**解密结果不落日志、不进缓存**；
- **展示**：列表/提醒/日志入口一律显示脱敏掩码（`110101********1234`），明文只在用户自己查看详情时短暂出现；
- **密钥轮换**：预留 `doc_keeper` 加字段支持按版本轮换密钥（`key_version`），更新密钥不影响已存密文可读。

### 5.4 安全加固汇总

- 登录/注册/短信类接口限流（Redis 计数，1 分钟窗口，失败放行并告警）；
- 密码最小 8 位 + 弱口令黑名单；JWT_SECRET/ENC_KEY 长度不足启动即拒；
- 所有写接口权限校验（本人/家庭范围/admin）以后端为准，前端守卫只做体验；
- 敏感明文绝不写入审计日志、导出默认脱敏、CORS 白名单、无跨域凭据通配。

### 5.5 权限矩阵（后端为最终边界）

| 能力 | user | 家庭管理员(同user) | admin |
| --- | :---: | :---: | :---: |
| 本人证件档案增删改查 | ✅ 本人 | ✅ 全家 | — |
| 本人到期日历/提醒 | ✅ | ✅ 全家 | — |
| 查看续办指南 | ✅ | ✅ | ✅ |
| 导出本人数据 | ✅ | ✅ | — |
| 维护证件类型/续办指南 | — | — | ✅ |
| 审计日志 | — | — | ✅ |

前端 `router/index.js` 同步做路由守卫（用户无管理入口），拦截以后端为准。

## 6. 数据库架构

单库 `doc_keeper`，12 张表：

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `users` | 用户与角色 | `username`、`password_hash`、`role`（user/admin）、`province_code`、`default_timezone` |
| `document_types` | 证件类型（种子） | `code`、`name`、`issuer`、`valid_years`、`default_ahead_days`(JSON)、`desc` |
| `provinces` | 省份知识库（种子） | `code`、`name`、`jtw_code`（交管 12123 子域名码）、`portal_name`、`portal_url` |

| `my_documents` | 用户证件档案 | `user_id`、`document_type_id`、`title`、`doc_number_cipher`、`expire_date`、`start_date`、`valid_years`、`status`、`note` |
| `reminder_rules` | 提醒规则 | `document_id`、`ahead_days`、`enabled` |
| `reminder_jobs` | 已生成的提醒 | `document_id`、`rule_id`、`remind_on`、`status`（唯一索引去重） |
| `family_members` | 家庭空间 | `host_user_id`、`member_name`、`member_color`、`share_scope` |
| `export_logs` | 导出记录 | `user_id`、`time`、`scope`、`file_hash` |
| `audit_logs` | 管理员审计 | `admin_id`、`action`、`target`、`detail`(脱敏)、`time` |
| `system_configs` | 系统设置 | `key`、`value`（提醒开关、保留期、缓存 key 前缀） |
| `app_notifications` | 每日通过弹窗/站内提醒 | `job_id`、`user_id`、`document_id`、`status`（PENDING/DONE） |

#### 省份与链接直达（本次新增）

证件办理的官方入口各省不同（如交管 12123 有 31 个省级子域名、政务服务各有平台名）。三件套配合实现"一键直达本省"：

```text
users.province_code  用户在设置/指南页选择，存用户档案
provinces.jtw_code   交管子域名码（gd/zj/xz…）→ https://{jtw_code}.122.gov.cn/
provinces.portal_url 省政务平台入口（粤省事/浙里办/京通…）

renewal_guides.link_mode 三种模式：
  FIXED           链接全国统一，直接用 official_url（如国家移民局）
  PROVINCE_JTW    按用户省份拼 12123 子域名（身份证/驾驶证/行驶证/年检）
  PROVINCE_PORTAL 按用户省份跳省政务平台（居住证/社保卡等）
  + region_code 非空 = 该省专属版指南，链接本身就是本省入口
```

前端 `store/links.js` 的 `resolveEntry()` 负责最终解析：有本省版指南用本省版；没设置省份或该省链接未收录时回退全国平台并在按钮下注明原因，绝不给死链。

### 6.1 SQL 的职责边界（重要）

`database/sql/` 只有两个脚本：

- `01_schema.sql`：建库 + 11 张空表；
- `02_seed.sql`：**种子数据**——31 个省份（名称/交管码/政务平台入口）、证件类型与续办指南（只读知识库，来自政务官方办事指南，见《项目介绍.md》第 5 节示例）。

普通用户档案、提醒规则、家人分组、提醒记录全部由前端页面产生写库，**用户全程不接触 SQL**。种子数据允许被管理后台调整（非关键字只读保护），后续结构变更一律新增 `03_xxx.sql`。

## 7. 数据维护体系（续办指南知识库）

> 本章回答：**一套"要带什么/去哪办/多少钱"的办事指南，凭什么信、凭什么敢信？**

| 原则 | 具体做法 |
| --- | --- |
| 官方来源必标 | 每条指南必须有 `source`（来源网站名）与 `updated_at`，禁止空来源 |
| 以当地为准免责 | 通用版 + 明确提示"以当地窗口实际要求为准"，降低过度自信 |
| 管理员可维护 | 指南只读给用户，可改给 admin；改动计入审计日志 |
| 不代填不代办 | 只给官方入口跳转，绝不代填政务系统、不承诺代办成功 |
| 缺失不编造 | 没有核实到来源的条目不写，宁可少一条也不编一条 |

## 8. Redis 使用边界

Key 前缀 `doc-keeper:`：

| 类型 | 示例 | TTL/策略 |
| --- | --- | --- |
| 提醒去重快通道 | `doc-keeper:reminder:{doc}:{rule}:{date}` | 24 小时 |
| 限流计数 | `doc-keeper:rate:{scope}:{ip}` | 1 分钟窗口 |
| JWT 注销 | `doc-keeper:jwt:revoked:{jti}` | 到 Token 过期为止 |
| 首页聚合缓存 | `doc-keeper:cal:{user}` | 短 TTL，变更即失效 |

缓存读写失败时：读取失败回退数据库；写入失败不影响业务响应；限流失败放行并告警；**提醒去重不依赖 Redis 正确性**（数据库唯一索引是最终保障）。

## 9. API 契约

## 10. 前端架构

- `api.js` 统一注入 `Authorization`，保存 `doc_token`、`doc_user`；401 时清理会话跳登录。
- `router/index.js` 按角色守卫：用户无管理入口，admin 有指南维护。
- `store/links.js` 省份与指南入口中枢：拉取省份表+指南表，`bestGuide()` 本省版优先，`resolveEntry()` 按 `link_mode` 把入口解析成真实 URL，`setMyProvince()` 保存用户省份。
- `styles.css` 全局设计系统：CSS 变量定义配色（品牌蓝紫渐变）、圆角、双级阴影、卡片/磁贴/chip/分段按钮等通用组件，全部页面共用一套视觉语言。
- `Dashboard`：今天的到期、未来 30 天待办、已过期数、最近提醒，渐变头部 + 卡片栅格。
- `DocumentForm`：**全点选录入**——① 证件类型点磁贴（自动带出名称/常见年限/推荐提醒档）；② 有效期"签发日+年限自动算到期"或"直接填到期日"双模式；③ 归属成员点选；④ 提醒档位多选 chip；证件号/备注收进"选填"折叠区。
- `Documents`：我的证件卡片流，按到期排序；卡片含状态徽章（正常绿/临期橙/过期红/归档灰）、按状态的图标底与数字着色、到期进度条与剩余百分比、口语化剩余时长（"约1年2个月"）；未填号码显示"去完善"引导，号码与有效期脱敏展示；主按钮「官方入口」按省份一键直达。
- `Calendar`：月历，按临期分级着色；点某天看当天到期项与续办入口。
- `Reminders`：我的提醒列表，设多档提前量、标记已处理。
- `Guides`：顶部省份选择条 + 分类筛选胶囊；每类指南自动选最佳版本（本省版 > 全国版），入口按钮直达本省平台，未收录时回退全国平台并注明（本页不再提供全文搜索框，改用分类点选直达）。
- `Settings`：省份选择（与指南页联动）、账号信息、CSV 导出。
- `Family`：家庭成员管理，新增成员自动分配配色。
- `AdminGuides`：管理员维护指南（材料/地点/费用/时限/官方入口/来源必填，支持省份版与链接模式）。

**配置类页面遵循同一底线**：改前能预览影响（改到期日会提示"将影响其提醒计划"），改后立即生效，改错能改回来。

## 11. 配置和启动

环境变量：`DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASSWORD`、`REDIS_URL`、`JWT_SECRET`、`APP_PORT`、`CORS_ALLOWED_ORIGINS`。

本地配置写入 `backend/.env`（已 Git 忽略）。Redis 未配置时允许启动并自动降级（提醒幂等走 DB 兜底）。

`scripts/start.ps1` 启动、`scripts/stop.ps1` 停止：启动脚本会预检环境（Python/Node/MySQL[3306]/Redis[可选]）→ 建 venv 装依赖 → 首次生成 `.env` 并问一次 MySQL 密码 → 建库建表并**只在空库时**补种种子（`init_db.py`，幂等、绝不删用户数据）→ 启动 FastAPI 8000 与 Vite 5173 → 轮询 `/api/health/ready` 后自动打开浏览器。根目录「启动-证件管家.bat」「停止-证件管家.bat」即是对这两个脚本的中文入口。

## 13. 安全和数据边界

- 认证：**Access Token（短时效）+ Refresh Token + 注销黑名单**的 JWT 体系；Token 带签名防伪，篡改即验签失败。
- 密码：Argon2/BCrypt 单程哈希存储，明文永远不落库。
- **证件号等敏感字段 AES-256-GCM 密文落库**（`ENC_KEY` 密钥只存环境变量），列表/日志/导出一律脱敏掩码，明文仅在本人查看详情时由服务端解密且不落日志。
- 不把数据库密码、JWT 密钥、加版密钥提交到 Git。
- 提醒内容只含必要信息，不包含其他用户数据。
- 公告与指南只来自知识库，标注来源；不代填、不代办。
- CORS 使用明确允许来源，不允许通配符凭据跨域。
- 审计日志只写操作类型、目标与脱敏摘要，不写证件明文与完备信息。
